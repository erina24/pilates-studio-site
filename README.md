# KOKYU PILATES

KOKYU PILATESは、ピラティススタジオのスタッフが、お知らせ・インストラクター紹介・体験料金を自分で更新できるWebサイトのデモです。私自身のピラティス事業の運営経験をもとに、スタジオが日々発信する情報の中から、この3つを更新対象に選びました。

このデモでは、体験料金やキャンペーンを変更するたびに、スタッフが制作担当者へサイトの更新を依頼する架空のスタジオを想定しています。依頼から反映までに時間がかかると、体験レッスンを検討している方が古い料金や案内を目にする可能性があります。

そこで、スタッフがmicroCMSの管理画面から情報を編集・公開し、サイトで反映を確認できる構成にしました。来訪者はトップページで体験料金を確認し、料金・サービスページでレッスンの詳細を読めます。

ポートフォリオとして、CMSの設計と実装に加え、スタッフ向けの更新手順と、変更が反映されないときの確認手順もまとめています。

**公開デモ**　[KOKYU PILATES](https://pilates-studio-site-two.vercel.app/)（ログイン不要）

## 制作のベース

microCMS公式の[「シンプルなコーポレートサイト」テンプレート（GitHub）](https://github.com/microcmsio/nextjs-simple-corporate-site-template)をベースに制作しました。ライセンスは、このリポジトリの [LICENSE](./LICENSE) を参照してください。

### 公式テンプレートから引き継いだ部分

Next.jsのページ構成、`microcms-js-sdk` を使ったmicroCMSへの接続設定、お知らせの一覧・詳細ページとメンバー紹介ページの基本構成を引き継ぎました。

### 今回追加・変更した部分

- **料金・サービスの管理と表示**。体験レッスンのプラン名・料金・説明を管理する `plans` APIを設計し、料金・サービスページとトップページの体験料金帯を追加しました。来訪者はトップページで料金を確認し、そのままレッスンの詳細へ進めます。
- **スタッフが更新を完結できる仕組み**。体験プランをコンテンツIDで参照し、プラン名を変えても同じプランの料金が表示されるようにしました。料金データはページへのアクセス時に取得するため、スタッフがmicroCMSで変更を公開し、サイトを再読み込みして反映を確認できます。
- **ピラティススタジオ向けのUI**。スタジオ写真や配色を取り入れ、メニューを「お知らせ」「インストラクター」「料金・サービス」に整理しました。PCでもスマートフォンでも、体験レッスンの情報を探しやすい構成にしています。

## デモで体験できること

### 来訪者の流れ

1. トップページで、スタジオの雰囲気と体験レッスンの料金を確認します。
2. 「体験レッスンを見る」ボタンまたは写真の下の料金帯から「料金・サービス」ページへ進み、プラン名・料金・レッスン内容を確認します。
3. 「インストラクター」で担当やプロフィールを確認し、「お知らせ」の一覧から気になる記事の詳細を開きます。

### スタッフの更新の流れ

1. microCMSの管理画面で「料金・サービス」を開き、「はじめてのピラティス体験レッスン」を選びます。
2. 「料金（円）」欄に新しい金額を数字だけで入力します。桁区切りと「円」はサイト側で表示します。
3. 変更内容を確認して「公開」を押します。
4. サイトのトップページと「料金・サービス」ページを再読み込みし、変更後の料金を確認します。

**動作確認済み**　ローカルで起動した本番用ビルドで、体験料金を2,500円から2,800円に変更・公開しました。「料金・サービス」ページ（`/plans`）を再読み込みすると、再ビルドせずに2,800円が表示されることを確認しました。

お知らせとインストラクター紹介も、対応するmicroCMSのコンテンツを管理画面で編集・公開する運用を想定しています。

## 技術構成と設計意図

| 技術 | 役割 |
| --- | --- |
| Next.js 16 / React 19 | App Routerでページを構成し、サーバー側でCMSのデータを取得して表示 |
| TypeScript | プラン・記事・インストラクターなど、CMSから取得するデータの型を定義 |
| microCMS / microcms-js-sdk | スタッフが管理画面でコンテンツを編集・公開し、サイトがContent APIから取得 |
| CSS Modules | ページやコンポーネントごとにスタイルを管理し、PCとスマートフォンで読みやすいレイアウトに調整 |

実装は [CMSデータの取得](app/_libs/microcms.ts)、[トップページの体験料金帯](app/page.tsx)、[料金・サービスページ](app/plans/page.tsx)、[トップページのレスポンシブスタイル](app/page.module.css) から確認できます。

### CMSで公開した変更をサイトに反映する

スタジオのスタッフが、体験料金を変更するたびに制作担当者へコードの修正や再ビルドを依頼せずに済むよう、サイトへのアクセス時にmicroCMSから料金を取得します。

- **`await connection()`** は、ページへのリクエストを待ってから、その後の処理を実行するための設定です。トップページと料金・サービスページでは、ビルド時の料金を使ってページを事前生成することを避けるために使っています。
- **`cache: 'no-store'`** は、CMSへの取得リクエストでNext.jsのデータキャッシュを使わないための設定です。料金・お知らせ・インストラクターの取得に指定しています。

スタッフは、変更を公開したあとにサイトを再読み込みして反映を確認できます。トップページの体験料金帯は、プラン名を変更しても同じプランを取得できるよう、コンテンツID（`TRIAL_PLAN_ID`）で参照しています。体験プランを別のコンテンツに差し替える場合は、参照するIDも更新します。

### コンテンツと表示の対応

| APIエンドポイント | 主なフィールド | 表示先 |
| --- | --- | --- |
| `plans` | `name`、`price`（数値）、`description` | トップページの体験料金帯（`/`）、料金・サービス（`/plans`） |
| `members` | `name`、`position`、`profile`、`image` | インストラクター紹介（`/members`） |
| `news` | `title`、`description`、`content`（リッチエディタ）、`thumbnail`、`category` | トップページ（`/`）、お知らせ一覧（`/news`）、記事詳細（`/news/[slug]`） |

公式テンプレート由来の `categories` と `meta` は補助的な設定です。お知らせのカテゴリは、記事に参照データがある場合に表示します。`meta` はサイトのメタ情報に使い、取得できない場合は既定値を使います。

プラン・記事・インストラクターが0件の場合は、それぞれ案内を表示します。お知らせに画像がない場合はタイトルと日付を表示し、インストラクターの写真が未登録の場合や仮画像の場合は、名前・担当・プロフィールを表示します。

## 運用とサポート

体験料金が表示されない、または変更前の金額が表示される場合は、管理画面での公開、APIでの取得、サイトでの表示の順に確認します。

### 1. スタッフが管理画面で確認する

microCMSの「料金・サービス」で「はじめてのピラティス体験レッスン」を開き、「料金（円）」に変更後の金額が入っていることを確認します。変更が下書きの状態なら、内容を確認して公開します。

公開後にサイトを再読み込みし、トップページの料金帯と「料金・サービス」ページの両方を確認します。解決しない場合は、**どのページで、いくらに変更したあと、何が表示されたか**を開発者に伝えます。

### 2. 開発者がAPIの結果を確認する

microCMSの「料金・サービス」一覧からAPIプレビューを開き、`plans` を `GET` で取得します。公開サイトと条件を揃えるため、下書き取得用の `draftKey` は付けません。

| APIの結果 | 次に確認すること |
| --- | --- |
| `200` で対象プランの `price` が変更後の金額になっている | APIから公開済みの料金を取得できています。サイト側の確認へ進みます。 |
| `200` で対象プランが見つからない、または `price` が変更前の金額になっている | 対象のスタジオとプランを開いているか、変更が公開済みかを確認します。 |
| 取得エラーが返る | エラー番号とメッセージを確認し、接続先のサービス、エンドポイント、APIキーの `GET` 権限を調べます。 |

### 3. 表示されないページに応じて調べる

APIで変更後の料金を取得できたら、どのページで問題が起きているかを確認します。

- **料金・サービスページ（`/plans`）には反映され、トップページの料金帯だけが表示されない場合**は、`TRIAL_PLAN_ID` が対象プランのコンテンツIDと一致するか確認します。料金帯は、対象プランを取得でき、`price` が数値の場合に表示されます。
- **両方のページに反映されない場合**は、確認中のサイトがAPIプレビューと同じmicroCMSサービスに接続しているか、`MICROCMS_SERVICE_DOMAIN` とAPIキーの設定を確認します。サーバーログも確認し、CMSからの取得時にエラーが出ていないかを調べます。

## ローカルでの起動方法

### 1. リポジトリを取得する

Git、Node.js 26.x、npmを用意します。ターミナルで次を実行してください。

```bash
git clone https://github.com/erina24/pilates-studio-site.git
cd pilates-studio-site
node -v
```

`node -v` が `v26.` で始まることを確認します。以降のコマンドは `pilates-studio-site` フォルダで実行します。

### 2. microCMSで3つのAPIを作る

microCMSで空のサービスを作成します。管理画面の「コンテンツ（API）」から「新しいAPIを作成」→「自分で決める」と進み、次の3つのAPIをすべて**リスト形式**で作成します。エンドポイントとフィールドIDは、表の英字をそのまま入力してください。

| API名 | エンドポイント | フィールドIDと種類 |
| --- | --- | --- |
| お知らせ | `news` | `title`（テキストフィールド）、`description`（テキストエリア）、`content`（リッチエディタ） |
| インストラクター | `members` | `name`（テキストフィールド）、`position`（テキストフィールド）、`profile`（テキストエリア）、`image`（画像・任意） |
| 料金・サービス | `plans` | `name`（テキストフィールド）、`price`（数字）、`description`（テキストエリア） |

付属の `microcms-template.json` は制作ベースの公式テンプレートの定義です。`plans` が含まれていないため、この手順では上の表に沿って設定します。

### 3. サンプルを1件ずつ公開する

各APIの一覧で「＋追加」を押し、以下を参考に入力して「公開」を押します。各一覧でステータスが「公開中」になっていることを確認してください。

| API | サンプル |
| --- | --- |
| お知らせ | タイトル「ピラティス体験レッスンのご案内」、概要「初めての方向けの体験レッスンです。」、本文「インストラクターと一緒に、呼吸と基本の動きを練習します。」 |
| インストラクター | 名前「佐藤 美咲」、担当「初心者向け・体験レッスン」、プロフィール「呼吸と基本の動きを一つずつ丁寧にお伝えします。」 |
| 料金・サービス | プラン名「はじめてのピラティス体験レッスン」、料金 `2800`、説明「呼吸と基本の動きから始める体験レッスンです。」 |

公開した体験プランを開き、編集画面のURL末尾にある**コンテンツID**を控えます。たとえばURLが `https://your-service-domain.microcms.io/apis/plans/abc123` なら、IDは `abc123` です。リポジトリの `app/_constants/index.ts` を開き、`TRIAL_PLAN_ID` の値をそのIDに書き換えます。

### 4. 接続情報を `.env` に設定する

microCMSの管理画面で、`news`・`members`・`plans` を読み取れる `GET` 権限のあるAPIキーを確認します。`package.json` と同じフォルダに `.env` を作り、次の例を貼り付けます。

```dotenv
MICROCMS_SERVICE_DOMAIN=your-service-domain
MICROCMS_API_KEY=your-api-key
BASE_URL=http://localhost:3000
```

- `MICROCMS_SERVICE_DOMAIN` には、管理画面のURLが `https://your-service-domain.microcms.io` の場合、`your-service-domain` の部分を入れます。
- `MICROCMS_API_KEY` には、先ほど確認したキーの値を入れます。
- `BASE_URL` には、ローカルで開くサイトのURLを指定します。省略時は `http://localhost:3000` が使われます。

`.env` はGitの除外対象です。APIキーの実値は `.env` で管理してください。

### 5. 起動して体験料金帯を確認する

```bash
npm ci
npm run dev
```

ターミナルに表示された `Local` のURLをブラウザで開きます。通常は [http://localhost:3000](http://localhost:3000) です。

1. トップページのスタジオ写真の下に、**「体験レッスン 2,800円」** の帯が表示されることを確認します。
2. 料金帯をクリックし、「料金・サービス」ページ（`/plans`）で、登録したプラン名・料金・説明が読めることを確認します。
3. 「お知らせ」と「インストラクター」を開き、それぞれ公開したサンプルが表示されることを確認します。

`/plans` に体験レッスンが表示されていて、トップページに料金帯が出ない場合は、`TRIAL_PLAN_ID` が公開した体験プランのコンテンツIDと一致しているか確認します。

### 本番用ビルドで確認する場合

開発サーバーを `Control + C` で停止してから、次を実行します。

```bash
npm run build
npm run start
```

ターミナルに表示されたURLを開きます。microCMSで体験料金を変更・公開したあと、トップページと `/plans` を再読み込みすると、再ビルドせずに変更後の料金を確認できます。

## 確認済みの内容と今後の改善

### ローカルで確認済み

- **CMSでの料金更新**。ローカルで起動した本番用ビルドで、体験料金を2,500円から2,800円に変更して公開しました。料金・サービスページ（`/plans`）を再読み込みすると、再ビルドせずに変更後の料金が表示されました。
- **PC幅・スマートフォン幅での表示と操作**。トップページ、料金・サービス、インストラクター紹介、お知らせ一覧と記事詳細を確認しました。トップページから料金ページへ進めること、記事詳細から一覧に戻れること、スマートフォンのメニューから各ページを開けることを確認しました。
- **ビルド**。UI修正後に `npm run build` が成功し、TypeScriptのチェックを通過しました。
- **コード上の確認**。体験プランをコンテンツIDで参照する処理、一覧が空の場合の案内、インストラクターの写真がない場合の表示処理を確認しました。

### 公開環境で確認済み

- Vercelの本番URLをシークレットウィンドウで開き、ログインせずにトップページから料金・サービスページへ進めることを確認しました。
- microCMSで体験料金を2,800円から2,900円に変更して公開し、トップページの料金帯と料金・サービスページ（`/plans`）を再読み込みしました。Vercelで再デプロイせずに両ページに2,900円が表示され、microCMSで2,800円に戻して公開した後も、両ページに反映されることを確認しました。

### 今後の改善案

- このデモ専用のCMSスキーマとサンプルデータを用意し、別のmicroCMS環境でデモを再現する手順を短縮します。
- CMSからデータを取得できなかった場合に、来訪者向けの案内を表示し、開発者が原因を調べるための情報をサーバーログに残します。
- 料金やお知らせの入力ルールと公開前のチェック項目をまとめ、担当者が変わっても同じ手順で更新できるようにします。
